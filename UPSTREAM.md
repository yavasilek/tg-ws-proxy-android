# Перенос Flowseal в Android

Источник: [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy), версия 1.11.3,
ветка main на коммите `50d539c718f1689c0437b7cf623e5995018c01e3` от 31.10.2026.
База Android: `amurcanov/tg-ws-proxy-android@540e588`.
Точная точка сравнения хранится в [upstream.json](upstream.json).

Сетевой движок остаётся на Rust. Python не входит в APK. Это перенос поведения,
поэтому обновления оригинала требуют проверки и адаптации исходников Rust.

| Изменения оригинала | Реализация Android |
| --- | --- |
| HTTP/2 для CF-медиатрафика, общая TCP/TLS-сессия и отдельные потоки запросов | `src/h2media.rs`, пул по имени сервера; 64 запроса на соединение, 8 на клиентский канал |
| Ограничения памяти и backpressure | Пакет до 4 МиБ, запросы/ответы канала до 8 МиБ, бюджет соединения до 32 МиБ; разрешения освобождаются при завершении и отмене |
| Восстановление зависших запросов и опрос продолжения | История до 16 пакетов / 64 КиБ на 30 секунд, до 3 повторов, до 2 параллельных повторов; зависшие заголовки не блокируют новые пакеты |
| Исправления padded intermediate и Android/Apple padding | Проверка длины незашифрованного пакета и до 256 байт внешнего заполнения |
| Ошибки MTProto, включая HTTP 404 и бинарный `-404` | Отрицательный код передаётся клиенту в его транспортном формате с повторным шифрованием |
| Таймауты H2 и освобождение ответных буферов | Таймаут бездействия каждой сетевой операции, RAII для квот и потоков, отмена пула при остановке |
| Новая маршрутизация WebSocket-пула | Готовое прямое соединение имеет приоритет; промах сразу ведёт к fallback, без дополнительных прямых попыток в обработчике клиента |
| Разделение обычных, media и test DC | Отдельные ключи пула и `/apiws_test` для тестового окружения |
| Ротация и backoff пополнения пула | Пул продолжает пополнение после истечения последнего соединения; fronting и обычный TLS проверяются по одному разу на домен |
| TCP fallback backoff | Одна одновременная попытка на адрес, экспоненциальная задержка 30-3600 секунд; TCP Telegram всегда использует порт 443 |
| TLS / certifi и исправление большого ClientHello | Проверка цепочки и имени через rustls/webpki; fronting отключает только проверку имени; исходящая группа X25519 без ML-KEM |
| Fake TLS из PR #1473 | Разбор предложений клиента, выбор cipher suite, X25519 или гибридный key share, HMAC всего ответа, короткая задержка и профиль первого ApplicationData маскирующего сайта |
| Оптимизация шифрования и разделения сообщений | Клонирование CTR за O(1), полный 128-битный счётчик, использование уже расшифрованных данных в splitter без третьего прохода AES |
| Отмена фоновых задач и закрытие CF Worker-пула | Реальное пополнение вместо прежней заглушки, cancellation token и закрытие при остановке |
| Удаление WebSocket keepalive из оригинала | Убраны периодические ping и искусственное отключение простаивающего моста через 120 секунд |
| Настройки ядра | HTTP/2, порт 80 для CF, Worker-домены, Fake TLS, тестовые DC, PROXY v1 и размер буфера доступны в Android-настройках |
| Диагностика | Счётчики H2, маршруты, ошибки запросов и транспорта; секреты не выводятся в журнал |

Особенности Android: сохранены Compose, foreground service, плитка, автозапуск,
уведомления, журнал и интеграция с Telegram. Десктопные оболочки Tk/pystray,
обновляторы Windows/Linux/macOS, Docker и подпись Windows-бинарников не включаются
в Android-приложение. Их функции заменяет Android-оболочка.

Дополнительно обновлена JNA с исправлениями Android 16-КиБ страниц. Для отдельных
установки и подписи форк использует пакет `com.yavasilek.tgwsproxy`.
Пакеты классов оставлены прежними для небольшого и проверяемого изменения.

Проверки выполняются тестами Rust, `tests/smoke_native.py` и Android instrumentation.
Локально прошли 17 тестов Rust, 5 циклов проверки C ABI и 4 instrumentation-теста
на Android 16 / API 36. Android Lint завершился без ошибок. Собраны arm64, arm32
и universal APK; проверены подпись, 16-КиБ выравнивание и соответствие упакованных
библиотек результату нативной сборки после стандартного stripping.
Минифицированная release-сборка также проверена запуском и остановкой сервиса на эмуляторе.
Замеры батареи, throughput и устойчивости в конкретной мобильной сети требуют
реального телефона; результаты эмулятора не заменяют такую проверку.

## Изменения Android 1.3.2

- WakeLock имеет ограничение 30 секунд и продлевается по точным счётчикам трафика.
  Открытое соединение без трафика больше не удерживает процессор постоянно.
  В простое статистика опрашивается раз в 15 секунд, без сети - раз в 30 секунд.
- Наблюдение за сетью учитывает маршрут приложения, в том числе VPN. Смена маршрута
  или возврат сети пересоздаёт соединения после задержки 1,2 секунды. События одной
  сети объединяются, изменение только проверки интернета не вызывает перезапуска.
  Android 5/6 использует системное уведомление об изменении подключения.
- Запуск, перезапуск и остановка ядра выполняются последовательно; завершение старого
  запуска и возврат сети не отменяют явную остановку пользователем.
- Экран и уведомление различают отсутствие сети, переподключение и запущенный прокси.
  Состояние локального слушателя не выдаётся за проверку связи с Telegram.
- Добавлены ошибки отдельных полей, редактируемый текст буфера, пояснения опасных
  сетевых опций и подтверждаемый сброс только настроек движка. Сброс Fake TLS требует
  повторно применить прокси в Telegram, о чём предупреждает диалог.
- Исправлены обращения к плитке и буферу обмена на старых Android.

Эти изменения не затрагивают механизм обновления приложения. Экономию батареи
в процентах и устойчивость ночной работы нужно измерять на реальном телефоне.

Проверка 1.3.2: 17 тестов Rust и 13 Android instrumentation-тестов на API 36,
включая Wi-Fi -> мобильную сеть, авиарежим, возврат сети после явной остановки,
перезапуск с открытым клиентом и остановку во время запуска. Lint universalRelease:
0 ошибок. Вручную проверены очистка и замена буфера, подтверждаемый сброс настроек,
запущенный foreground service без WakeLock в принудительном Doze и статус после
выхода из Doze. Для универсального APK проверены подпись, выравнивание 16 КиБ
и совпадение обеих нативных библиотек с новой сборкой после stripping.

## Журнал и диагностические отчёты Android 1.3.3

Сбор больше не зависит от команды logcat, её формата, прав прошивки или жизни
Activity. Rust хранит ограниченную очередь из 512 записей и передаёт её через
`DrainLogs` / JNA; переполнение отмечается предупреждением. События ProxyService
поступают прямо в журнал приложения. Старый парсер пропускал этот тег, а ошибки
самого сборщика скрывались. Сбор запускается в Application, включая запуск без UI.

Последние 500 очищенных записей с временем сохраняются атомарно в приватном файле.
Новый запуск прокси не стирает историю; очистка доступна пользователю. Повторные
соседние сообщения объединяются. Сохранённый ранее фильтр NULL теперь означает
показ всех записей, а не скрытие журнала. Ошибки сбора и сохранения видны в журнале.
Журнал исключён из резервного копирования и переноса данных.

Вкладки «Логи» и «Информация» открывают общий диалог отчёта: описание проблемы,
формирование, предпросмотр, копирование или передача TXT через системное меню.
Включаются версия, Android, модель устройства, ABI, тип сети, энергосбережение,
обезличенные параметры движка, счётчики и последние события независимо от фильтров.
Секреты стандартных форматов, URL, IP, домены и заголовки авторизации очищаются до
показа и сохранения. Нет SSID, fingerprint, серийного номера, Android ID или значений
Worker/Fake TLS доменов. Предпросмотр остаётся необходимым для произвольного текста.
FileProvider открывает только каталог временных отчётов и выдаёт временное право
чтения выбранному приложению. Автоматической загрузки или отправки отчётов нет.

Проверка 1.3.3: 18 тестов Rust и 19 Android instrumentation-тестов; покрыты прямые
логи сервиса без Activity, передача событий Rust, ограничение и очистка журнала,
удаление тестовых секретов до записи на диск, отчёт независимо от фильтров и чтение
TXT через content URI. В minified release вручную проверены восстановленная история
после force-stop, непустой экран логов, предпросмотр и системное окно отправки TXT.
Lint universalRelease: 0 ошибок. Подпись совпадает с 1.3.2, проверены выравнивание
16 КиБ и соответствие обеих библиотек новой нативной сборке после stripping.

## Следующее обновление оригинала

```sh
git remote add upstream https://github.com/Flowseal/tg-ws-proxy.git
git fetch --no-tags upstream main
python tools/upstream-status.py --check
```

Если remote уже существует, первую команду пропустите. После переноса новых изменений
обновите `upstream.json`, эту таблицу и тесты. Не передвигайте контрольный коммит
только ради зелёной проверки. Теги оригинала и Android-форка могут совпадать по имени;
поэтому обычное обновление выполняется с `--no-tags`.
